# 影游教学制作经验 · 曹冲项目

## 本案已经形成的可复用方法

1. 把知识变成决定的代价。同水线而人员改变，是一处能被学生发现、验证、纠正的剧情冲突，比让角色讲公式更能生成学习证据。
2. 每个有意义的选择写四项：当前所知、实际操作、可观察后果、后继条件。不能用“选择认真复核”自动修复记录。
3. 把分层落实到学习方法。故事版看、做、找、讲；实验版提问、计划、对比、解释、迁移。两版要有不同的学习产物与评价证据，不能只改变数字、字号或称呼。
4. 保留首次想法与修订证据。预测可错、账可改，日志不能因多试几次达到上限而卡住。界面反馈针对当前证据，不给学生贴人格标签。
5. 将影视段与操作段交接写进分镜。影片交代局势并提出问题，结束于操作前；动态数据由程序绘制，避免为每种状态生成视频。
6. 图像连续性要用具体物件检查：同船、人数、谁在岸上、三个木块是否还是三个。精美单张不能替代接镜。
7. 字幕、声音、人物台词和按钮说明共享同一镜头编号。保留真实收到的文件状态与哈希，避免目录完整但文件缺失。
8. 通过条件必须服务理解。水盆至少有两个不同自由漂浮观察及解释；最终还需一个换情境任务，才能检查是否只记住操作顺序。
9. 课堂产品允许慢、允许返、允许暂缓。渐进线索、可选朗读和显式修复入口，让操作挫败不掩盖学科问题。
10. 验收分开看工程、表达与学习证据。自动化能证明路径可走、规则一致；学生解释质量须来自课堂观察。记录新的证据再改设计。

## 下一次同类项目的检查卡

史料与教材定位 → 学习目标 → 学生身份 → 核心冲突 → 至少一条可证伪预测 → 可操纵变量 → 实际记录 → 有后果的选择 → 可恢复分支 → 迁移任务 → 角色/场景场记 → 音画字幕 → 全路径与键盘/小屏验收。

研究依据与本案对应见[教学设计研究](10-learning-design-research.md)；当前适用结果见[1.1验收报告](18-acceptance-v11.md)。这些是持续改进记录，不宣称已经形成未经检验的行业通用效果。


## 1.1新增的细节检查

- 核对动作之后的记录：卸下物件是否同步收起标签；修正标签后结果是否重新计算。
- 核对结尾之后的报告：暂定数值不能在下一页或打印页自动变成定论。
- 核对剧情后的声音：同一张图相似，不代表两条路线可共用同一段台词；四格讲述与书箱迁移必须各有镜头编号。
- 核对看得见的数量：四格必须对应四张卡；图案必须能让孩子直接认出物件。
- 先做可独立比较的两次操作，再要求说理由，避免只选一条正确句子就通过探究。

## 1.2新增的互动制作经验

- 每种玩法都要回答“学生借此学到什么”：连线帮助一物一记，拖曳让条件变化可见，拼图训练叙事先后，找变化练习识别单一条件。
- 拖动必须有点选替代，键盘替代也要保留；触摸松手后的点击不能再次加一块，取消不能留下半完成记录。
- 角色反馈要区分“称过”“记过”“人回来了”“水线对齐”“全部核对过”，不能把任何一个局部发现夸成最终正确。
- 陪伴层和影视层分开生产：两张四表情透明图只供界面，不把幼象伙伴混入历史称量镜头；已有旁白播放时避免重复朗读。
- 小游戏的印章和正式实验的记录分开。学生过了三关，并不意味着自己已经设计过公平比较。
- 不用个人反思和整份日志换取一句提示；模型仅接收学生主动提出的问题及当前必要状态，服务失败仍能继续学习。
- 复核所有主动动作产生的后果，包括小游戏展开状态、图卡放置位置、旧回答取消、旧存档恢复与打印内容。

研究与依据见[互动研究](19-play-companion-research.md)，执行稿见[伙伴与影视衔接](20-interaction-companion-production.md)，当前验收见[1.2报告](22-acceptance-v12.md)。这些经验来自本项目设计和功能验证，不等同于真实班级学习效果的研究结论。

## 1.3新增的设计与验收经验

- 先观察，再判断。把两次记录画在相同机位下，允许推拉与单独查看；不要先展示正确数字再要求学生选择。
- 记录顺序与因果方向要分开。A可以先记多木块，也可以先记少木块；判断实际A到B的变化后，再回到研究问题解释，不能把学生的保存顺序写死。
- 证据需要随操作改变。阿舟回船、石堆调整后，图证和已核对标记一起更新；不能保留一张看似精美但已过时的固定剧照。
- 用具体物品支撑迁移。先找出两栏中相同的船，再辨认砝码替代的书箱与工具，最后让学生自己计算。配对动画不能暗示真实船被拿走。
- 将修改猜想视为学习成果。保留原猜想、实际观察与修改原因；不奖励猜中、不因修正扣分。
- 新步骤只约束新任务。升级存档时保护正在进行的旧学习；学生主动开启新版后再启用新的关卡条件。
- 陪伴角色也要让出阅读空间。桌面与手机分别查看，手机首次使用先呈现小巧角色，反馈仍留在任务区并可被读屏读取。
- 视频接口需要提前模拟。把所有镜头视频字段设为非空，验证图卡、拼图和打印依然取静帧；等待回片后再检查真实编码与字幕。
- 以同状态、同视口对照视觉变化，再看局部文字与道具。首轮物品插画中的船舱、木宝箱和船桨均因不符场记而弃用。

依据见[学习互动研究](23-learning-interaction-research-v13.md)，落实见[制作衔接稿](25-reasoning-production-v13.md)，验收见[1.3报告](26-acceptance-v13.md)。以上是可复用的制作与验证经验；真实课堂中仍需收集学生解释、修改过程与教师观察，才能评价学习效果。

## 1.4新增的制作经验

- 学生没写的内容保留空白；参考讲法必须单列，不能署为“我的话”。允许口述，字数和页数不当能力分数。
- 排错题要修改真实条件，不能只选一句“只改一项”就通过；接受所有满足规则的合法解。
- 可选挑战独立保存，完整路线、复习路线、旧路线的回看与打印都需检查。
- 按钮在成功后被替换时，键盘焦点留在任务内，避免下一次按键误操作上方正式实验。
- 新组件命名要避开既有父级样式；只检查子元素的背景不足以发现祖先的深色底，必须实际看全景和局部截图。
- 中文输入不触发整页重绘；保存失败不显示成功，仍可保留当前页面并下载。

研究见[1.4研究](27-expression-repair-research-v14.md)，执行见[1.4衔接](28-workshop-production-v14.md)。


## v1.5：动作、记录与判断分开

直接操作应承载物体关系，不把手稳当理解。实验桌要分清当前摆法与已存证据，复原不应悄悄覆盖记录。保存、可比较、已解释是三种状态。触屏焦点自动滚动可能改变点击落点；键盘避让则要覆盖整个浮动面板与固定导航，不能只看头像。多指取消须检查第二指在画布外的情况。空白学习作品如实留白。依据与边界见[直接操作研究](30-v1.5-直接操作与实验引导研究.md)，实际验收见[1.5验收](32-acceptance-v15.md)。


## v1.6：把表征真正连起来

本轮从[IES表征建议](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)、[EEF反馈指南](https://educationendowmentfoundation.org.uk/education-evidence/guidance-reports/feedback)及PhET研究中提炼的做法，连同适用边界收录在[研究记录](33-transfer-feedback-research-v16.md)。

- 同坐标切图适合手机中的前后比较；不能因为研究讨论并列比较，就把两张难以辨认的小图硬挤在一起。
- 观察、改变条件、验证后果分别由学生完成。回看是参考，不改写当前船况。
- 把总量拆成对象份额，有助于解释减去的是谁；图解自动呈现的余量不能冒充学生独立计算。
- 通用“再试一次”不够具体。320、340等数值可对应检查方向，但不凭数值判断孩子的心理过程。
- 修订后主任务和伙伴都要撤销过期成功，不能只更新绿色标记而留下旧夸奖。
- 连续加减按钮的身份要稳定；动态数值不能参与焦点恢复标识。禁用边界要给焦点一个仍可操作的位置。
- 安全策略下内联样式可能不生效。数学图示须检查真实像素比例，不能只测文本和数据。
- 保持可选支架：会手算的学生直接继续，需要图解的学生随时试分。升级不靠增加必做次数。
- 迭代验收分为功能、视觉、制作连续性、课堂效果四层；本轮完成前三层，课堂效果留给真实试用。

实施见[执行稿](34-transfer-bridge-production-v16.md)，验收见[1.6报告](35-acceptance-v16.md)。

## v1.7：把表达权交给学生

[本轮原始与官方研究](36-presentation-retrieval-research-v17.md)支持提供适量回忆支架、邀请解释和用证据交流；不支持把“翻完四页”当成学会。设计将研究落实为自选提示、原始记录和只读展示。

- 作品编辑与面对同学讲述是两种场景。用大画面和稳定翻页控制服务讲述，原编辑器仍用于写作。
- 隐藏提示必须可逆；低年级可以指图或看自己的话，不奖励不求助。
- 原话、选择句、客观模型与参考讲法各有身份。缺失留空；不要把系统参考包装成孩子说过的话。
- 错误答案、首次结局和暂定判断也可以成为有价值的讨论材料，不能为“漂亮成果”洗成成功。
- 让学生讲话时，数字伙伴应安静下来。取消在途模型请求并阻止迟到回答；退出不自动恢复声音。
- 新展示不需要新存档字段：临时页码、文字展开与学习完成分离，旧作品自然可用。
- 浏览器原生模态可访问性仍需实测，Tab循环、返回焦点、长文字滚动和移动端固定导航都要覆盖。

执行见[1.7制作稿](37-showcase-production-v17.md)，工程证据见[1.7验收](38-acceptance-v17.md)。


## v1.8：让学生成为题目的创作者

[本轮研究](39-peer-challenge-research-v18.md)核读PhET、PBS KIDS、Scratch Foundation、Harvard Project Zero及IES/WWC的原始与官方资料。借鉴的是创造、交棒、观察和解释的活动结构，不把指南当成本应用教学效果证明。

- 出题权必须改变思考内容。藏哪幅图改变要解释的步骤；工具出现在哪一次改变重量关系。
- 补图与解释分开显示，避免解释先泄露被藏画面。藏首图和藏尾图需分别指向后面的画面与最后的任务，不能总说“看看前后两步”。
- 创作者、解题者承担不同任务，用交棒屏切换；无需真实姓名，也不用按钮假装验证口述。
- 每道题固定条件，换题明确换一箱书。题目图卡不冒充真实物体连续变化的模拟。
- 回代反馈引用学生的实际输入，分别呈现两次总重量和差值。数字错与关系错提供不同检查方向。
- 核对记录要有当前轮身份。两轮相同答案仍是两次实际作答；本轮重复点击或重选同值不重复留档，改题后不能冒出上一轮试算。
- 保存失败也要测试交棒屏等没有普通反馈区的状态；错误提示不能再次触发脚本异常。
- 学生文案使用短问题、具体物品和明确单位；算式单独一份不重复写“300=300克”，计算结果以括号标单位。
- 不为新增入口压缩故事图。桌面并列、手机滚动，关键按钮固定；帮助和自我修订不加罚分。

执行见[1.8制作稿](40-peer-challenge-production-v18.md)，工程证据见[1.8验收](41-acceptance-v18.md)。
