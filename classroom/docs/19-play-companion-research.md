# 趣味互动、学习伙伴与模型接口研究

核查日期：2026-10-10。适用项目：《曹冲称象：一线之差》。本文是制作与开发资料，补充 [10-learning-design-research.md](10-learning-design-research.md) 与 [16-mode-pedagogy-research.md](16-mode-pedagogy-research.md)。本轮只查公开一手资料，未使用凭据、未发送学生资料、未调用付费模型。标为“项目推导”的内容是本项目可实施方案，不是原研究验证过的产品效果。

## 1. 结论先行

增加连线、拖曳、拼图时，让学生移动的是**有意义的物品、步骤和比较条件**。故事版的小曹冲帮助学生观察并讲清办法；实验版的小象回应学生的真实发现，但不替学生选择条件、判定证据或完成实验。成功反馈应说清“你刚才做成了什么”，再连接下一步。

大模型可以负责因人而异的短提示和表达润色；水线、称量、记录、关卡、结局仍由确定的游戏规则判定。这样模型尚未接入或网络暂时不可用时，学习过程仍然完整。以上是结合下列依据作出的项目架构选择，不是 DeepSeek 的官方教学建议。

## 3. 适度、可以落地的交互组合

以下均为项目推导。每个主要节点选择一种核心玩法，不在同一屏堆齐所有小游戏。不给低年级设置速度排名；求助和选择替代操作不降低结局。

| 玩法 | 故事版做什么 | 实验版做什么 | 看得见的学习证据 | 依据 |
|---|---|---|---|---|
| 连一连 | 将“小船、记号线、小秤”与“留下前后可比较的位置、分批称东西”等简短用途相连；卡片旁有具体物件 | 把本次记录与它支持的说法相连；例如把“船工不在，石头多了一份”连到“要把多出的这一份查清” | 保留学生实际连接；错误时只指出本对关系的问题，不自动完成其余连线 | P01、P03、P05、P08 |
| 搬一搬 | 把有不同图签的筐放上船，看到船身变化；一筐对应一张记录，取回仍是同一筐 | 把“船工是否在船上”等条件卡放到“这次改变”或“保持一样”栏，再按计划做比较 | 货物、称量与记录数量一致；计划在实验后仍可回看，不被结果覆盖 | P01、P04、P05、P08 |
| 拼一拼 | 拼好四个动作片段，形成自己的故事长卷；每一片是一个完整动作，不做只看图案边缘的无关拼图 | 将“我的猜想、两次记录、发现、还要再查的事”放到报告相应位置；可从真实记录里选择 | 故事版留下顺序与自己的话；实验版留下记录和结论之间的联系 | P01、P02、P04、P08 |
| 对一对 | 翻看象上船与象下船后的两张图，找出船工、石头、水线的变化 | 固定两份试验记录，逐项查看哪些条件相同、哪一项改变 | 学生找到了哪一处差别；若同时改两项，保留这次尝试并引导补做，而非伪装成合格比较 | P03、P04、P08 |

### 操作细节应做到什么程度

- **连线**：拖线时起点保持选中，靠近可连接卡片时显示目标轮廓；也能“点左卡，再点右卡”。已连的关系同时写成短句，不只靠线条颜色。点已连关系可以撤回。
- **拖曳**：物品跟随手指，落点有清楚的轮廓；没有放进有效区域时回到原位并说“还没放进船里”，不算知识错误。完成一次放置只触发一次游戏动作，避免一次拖曳被同时当作点击处理。
- **拼图**：图块有标题，放好后仍可换位置；先选择图块再点空位也能完成。让学生根据动作先后判断，不用很小的碎片考验手眼速度。
- **触屏**：只在可拖元素上处理拖曳，画面其余部分仍可正常滚动。不能为了拖图块把整页滚动锁住。
- **键盘**：Tab 可到图块与目标，Enter 或空格可选取、放置；完成后焦点留在可继续操作的位置。点选和键盘都应得到与拖曳相同的记录。

前三条的学习意义由 P01、P08 支持；无需拖曳的点选替代直接对应 P05；尺寸、吸附、焦点和去重方式是工程推导，需要在实际触屏设备与浏览器中检查。

## 4. 两种伙伴应有不同职责

### 故事版：小曹冲是一起办事的伙伴

小曹冲站在任务旁，以短句邀请学生加入：“你来留线，我帮你看着水面。”他应回应本次行为，而不是每次都说“真棒”。学生停顿时，先给“要不要看看船边？”的轻提示入口，由学生决定是否展开；不要按等待秒数自动说出答案。

建议三级支架为：**先指看哪里 → 再提醒比较什么 → 最后演示一步**。一旦学生已经会做，就收起演示，不要求重复阅读。低年级的“我想听一遍”“给我一点提示”“我自己试试”三种选择均可保留。依据 P03、P04；具体角色语言为项目原创。

### 实验版：小象是观察伙伴

小象回应称量与发现，但保持与真实实验一致：装上一筐后先看船；学生留下记录时轻点脚或抬鼻；学生发现两次多改了一项时安静等待。它可以用旁边的短气泡问“这次只改哪一处？”，不能用兴奋动作暗示尚未验证的正确选项。

小象在读题、观察水线、比较表格时安静；成功后动作短暂出现，再回到稳定姿态。用“让伙伴安静一会儿”或统一的动作开关暂停陪伴动作，同时保留角色与文字。尊重系统的减少动态设置。依据 P02、P06；角色姿态和时机是项目推导。

### 共用事件规则

| 真实事件 | 可用动作 | 可用短句 | 不能发生 |
|---|---|---|---|
| 新任务出现 | 小曹冲招手一次；小象转头一次 | “这一回，你想先查什么？” | 角色始终跳动，抢走读题注意力 |
| 成功留下有效记号 | 指一下刚留的线，再安静 | “线留在船边了。船动时，它也跟着走。” | 水面未稳却提前庆祝“记号准确” |
| 放入一批并完成对应记录 | 点头或抬鼻一次 | “这一筐称过，也记下了。” | 只放上船就宣称已经称过、记过 |
| 学生修改了真实错误 | 温和点头 | “你找到了多记的那一筐，也改好了。” | 点击“检查”即算修正成功 |
| 请求提示 | 目光指向相关物品 | “先对照两张图，看看船工在哪儿。” | 提示同时覆盖界面、自动操作并给出结论 |
| 正在等待模型回答 | 稳定等待姿态与短状态 | “我们一起想一想。” | 无限转圈、挡住继续操作、把旧节点回答插进新节点 |

所有例句必须根据真实状态填入。纯装饰动作的推荐时长约 0.5—1.2 秒，属于本项目节奏目标，不是研究或规范规定的最优时长。动作暂停时，学习状态照常更新；不要把“动画停了”当作“实验不能继续”。

## 5. 成功反馈要具体到行为

项目采用“刚才的行动＋看见的结果；需要时再给下一步”的短反馈。局部成功与整个实验成立分开评价，避免一句“大功告成”越过后续检查。依据 P03、P07；以下为本项目文案。

| 学生刚完成的事情 | 建议反馈 |
|---|---|
| 正确连接小秤用途 | “连对了！小秤能把石头一批一批称出来。” |
| 完成一条关系，尚有其他关系 | “这一对连好了。再看看记号线有什么用。” |
| 把第二筐放到船上 | “第二筐上船了，船身又沉下去一点。” |
| 放下后没有进入目标 | “还没放进船里。也可以先点这筐，再点船。” |
| 留下两份条件可比较的记录 | “两次记录都留下了。这回只改了船工的位置，可以仔细比一比。” |
| 猜想与结果不一致 | “结果和刚才想的不一样。这个发现值得留下来。” |
| 重新核对后修正记录 | “你把重复的记录去掉了。现在一筐只记一次。” |
| 故事图卡顺序正确 | “四步排顺了。试着讲给没看过故事的伙伴听。” |

不把“排顺四张卡”写成“已经会讲故事”；不把“完成两次点击”写成“已经学会做实验”；不按拖得快慢评价聪明或认真。读屏只播报有意义的结果，不对指针每移动一像素连续播报。

## 6. DeepSeek 官方模型与接口核查

### 6.1 `deepseek-v4-flash` 确实存在过，但当前不宜作为默认显示名

官方更新日志记载，2026-04-24 开放 V4-Pro、V4-Flash，2026-07-31 更新 V4-Flash；2026-09-10 发布 V4.1-Flash，并说明旧模型名临时转向新模型。当前首页和模型页推荐 `deepseek-flash`，对应 DeepSeek-V4.1-Flash；`deepseek-v4-flash` 仍接受，但不代表仍运行原 V4-Flash。依据：[官方更新日志](https://api-docs.deepseek.com/updates/)、[当前模型页](https://api-docs.deepseek.com/quick_start/pricing/)、[调用首页](https://api-docs.deepseek.com/)。

**项目推导：** 配置项保留任意受服务端允许的模型标识；默认示例用 `deepseek-flash`。用户已有 `deepseek-v4-flash` 配置时，不把它判为拼写错误，但在教师/管理员配置说明中解释当前别名关系。学生界面只显示“小曹冲”或“小象伙伴”，不承担模型版本说明。

### 6.2 已核对的 OpenAI 兼容调用

| 项目 | 官方当前说明 |
|---|---|
| 基础地址 | `https://api.deepseek.com` |
| 请求 | `POST https://api.deepseek.com/chat/completions` |
| 请求头 | `Content-Type: application/json`；`Authorization: Bearer <服务端密钥>` |
| 必填正文 | `model` 和非空 `messages`；本项目只需 `system`、`user` 的文字消息 |

| 思考模式 | 默认开启；可用 `thinking: {"type":"disabled"}` 关闭。采用 OpenAI Python SDK 时，该扩展参数放在 `extra_body` 中 |

以下为**本项目建议的请求体示例**，没有实际发送。`512` 是短提示的初始预算建议，需接入时实测后调整，不是官方最优值。


### 6.3 配置与产品的职责分开

以下是工程推导，不是服务商条款摘要。

- 服务端持有基础地址、模型名、密钥和超时配置；浏览器只调用项目自己的伙伴接口。密钥不放学生页面、源码公开目录或浏览器存储。
- 只在学生主动“问伙伴”时发送一次请求；不随每次拖动、指针移动或装载自动请求。一般成功反馈用本地已审核文案立即出现。
- 输入只包含当前任务、已确认的游戏事实、学生当前问题和必要的短上下文；不需要姓名、学校、照片或完整学习档案。项目规则和学生输入分开组织。
- 模型返回只允许短 `reply`。返回中的数值和已完成动作必须与当前事实相容；涉及明确判定时，采用本地模板。不要把模型自由文本转成游戏指令。
- 绑定请求时的模式、节点和状态版本。回答返回前学生已换关或重做，旧回答不进入新的气泡；取消或丢弃即可。
- 限定长度、解析 JSON、空内容、非正常结束和超时均有降级路径。无法取得有效回答时，显示与当前任务相符的本地提示，例如“先看看船边的线，再试一试”，而不是展示接口错误码。
- 本地提示与模型提示都不能伪装成观察结果。没有真实发生“请回船工”，任何一句伙伴话都不能把该任务标成完成。

## 7. 尚未实测的内容与接入验收

以下记录留在制作文档，不加入学生故事页。

1. **模型服务可用性**：本轮确认的是公开官方文档中的模型名与接口，没有登录账号、核验余额或发起付费调用；不登记为“DeepSeek 联调通过”。别名的“临时”路由不能视为永久承诺，正式接入前重新查看官方模型页。
2. **中文儿童表达质量**：当前研究不证明该模型能稳定给出符合本项目年级的提示。接入后用已知状态测试短句、事实一致、不给出错误称量结论与不代做；使用真实儿童试教再调整语气。
3. **模型响应延迟**：超时与字数配置需要实际环境测量。本地反馈应立即完成，网络等待不能阻塞拖曳、查看记录和下一项已授权动作。
4. **触屏手感**：浏览器事件测试可以核对放置逻辑，不能替代不同平板上的真实拖曳、滚动、误触与字号观察。
5. **学习效果**：拼图完成率、互动次数和角色受欢迎程度不等同于理解。故事版看能否讲清步骤；实验版看能否用比较记录说明条件与结论。

### 最小验收清单

| 检查 | 通过的具体表现 |
|---|---|
| 三种输入等效 | 同一连线/移物/排序分别用拖曳、点选、键盘完成，最终记录一致 |
| 误放不算知识错误 | 拖出目标后物品复位，说明如何放置，没有扣除进度或错误贴标签 |
| 一次动作一次变化 | 一次拖曳只加一批；点击替代不会与拖曳回调叠加；取消拖曳不记完成 |
| 反馈符合事实 | 未称不说“称过”，未记不说“记好”，只改一筐不说“全部正确” |
| 动作可安静 | 暂停或减少动态时伙伴静止，文字和实验照常工作；读取水线时无无关持续晃动 |
| 不抢焦点 | 伙伴气泡与成功提示不自动夺走选中卡片或输入焦点；重要状态可被读屏获知 |
| 无模型也完整 | 未配密钥、超时、空回答、无效 JSON 时仍有适当本地提示，关卡可独立完成 |
| 回答不串关 | 请求后切换模式或节点，旧回答不能覆盖新节点；模型不能修改分数、状态、记录或结局 |
| 作品来自学生动作 | 故事长卷和实验卡准确反映本次排序、材料、记录与修改，不生成并不存在的成功过程 |

这些检查用于确认实现的完整性与一致性。教育意义仍要通过学生的讲述、解释、修订和迁移来观察，不能仅凭接口返回成功或所有图块拼好就宣布达成。
